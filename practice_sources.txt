3.2. Шаблоны Django 
Шаблон Django – HTML-документ, содержащий специальные конструкции 
языка шаблонов Django. Шаблон отвечает за представление данных. Например: 
<h1>{{ room.name }}</h1> 
<p>Вместимость: {{ room.capacity }}</p> 
Здесь {{ room.name }}  означает получение значения name объекта room. 
Сам объект передаётся из view-функции. Например: 
def room_detail(request, room_id): 
    rooms_list = load_rooms() 
    room = find_room_by_id(rooms_list, room_id) 
 
    context = { 
        "room": room, 
    } 
 
    return render(request, "rooms/room_detail.html", context) 
Таким образом, Python-код не формирует HTML-строку. Он подготавливает дан-
ные для страницы.

3.3. Функция render() 
Для формирования ответа на основе шаблона используется функция render(): 
from django.shortcuts import render 
Общий вид: 
return render(request, "имя_шаблона.html", context) 
где: 
• request – текущий HTTP-запрос; 
• второй аргумент – путь к шаблону; 
• context – словарь данных, передаваемых шаблону. 
Например: 
def rooms(request): 
    rooms_list = load_rooms() 
 
    context = { 
        "rooms": rooms_list, 
    } 
 
    return render(request, "rooms/room_list.html", context) 
В шаблоне: 
{% for room in rooms %} 
    <h2>{{ room.name }}</h2> 
    <p>Вместимость: {{ room.capacity }}</p> 
{% endfor %} 
Получается разделение ответственности: 
Компонент Ответственность 
URLconf определяет адрес страницы 
view получает и подготавливает данные 
context передаёт данные шаблону 
template формирует HTML 
CSS отвечает за оформление 
JavaScript реализует клиентское поведение 
3.4. Контекст  аблона 
Контекст – словарь, содержащий данные, которые должны быть доступны в 
шаблоне. Например: 
context = { 
    "rooms": rooms_list, 
    "page_title": "Помещения Roomly", 
}

9 
В шаблоне эти значения доступны по соответствующим именам: 
<h1>{{ page_title }}</h1> 
 
{% for room in rooms %} 
    <p>{{ room.name }}</p> 
{% endfor %} 
Важно соблюдать соответствие имён. Если во view используется: 
context = { 
    "rooms": rooms_list, 
} 
то в шаблоне необходимо обращаться к: 
{{ rooms }} 
а не к: 
{{ rooms_list }} 
если такая переменная отдельно в контекст не передавалась. 
3.5. Выражения {{ ... }} 
Для вывода значения в шаблоне используются двойные фигурные скобки: 
{{ variable }} 
Например: 
{{ room.name }} 
{{ room.capacity }} 
{{ booking.status }} 
Можно обращаться к атрибутам объектов, например {{ room.name }} , а 
также к элементам структур данных.  В ПР6 необходимо использовать шаблоны для 
отображения объектов предметной области: Room, User, Booking. 
При этом предметная логика продолжает находиться в Python -коде. Шаблон не 
должен превращаться в место реализации бизнес-логики.

3.7. Циклы в  аблонах 
Для перебора коллекции используется: 
{% for объект in коллекция %} 
    ...

Например:

Для пустой коллекции можно использовать empty:

{% endfor %} 
Это позволяет обрабатывать ситуацию, когда данные отсутствуют, непосред-

3.8. Наследование  аблонов 
Если каждая HTML-страница содержит одинаковые элементы: 
• DOCTYPE; 
• <head>; 
• подключение CSS; 
• меню; 
• контейнер страницы; 
• подвал 
Копировать этот код в каждый файл не следует. Для общей структуры использу-
ется базовый шаблон. Например: 
<!DOCTYPE html> 
<html lang="ru"> 
<head> 
    <meta charset="UTF-8"> 
    <title>{% block title %}Roomly{% endblock %}</title> 
</head> 
<body> 
 
    <nav> 
        ... 
    </nav> 
 
    <main> 
        {% block content %} 
        {% endblock %} 
    </main> 
 
</body> 
</html> 
Другой шаблон наследует эту структуру: 
{% extends "base.html" %} 
 
{% block title %} 
    Помещения 
{% endblock %} 
 
{% block content %} 
    <h1>Помещения</h1> 
{% endblock %} 
Такой подход позволяет изменять общую структуру сайта в одном месте.

3.11. Фильтры  аблонов 
Фильтры позволяют изменять представление значения непосредственно в шаб-

## 6. Django Template Language 
Шаблоны используют возможности Django Template Language. 
### Базовый шаблон 
Общий шаблон страниц: 
templates/base.html 
Он содержит общую HTML-структуру страницы, подключение стилей и JavaScript, навигацию и блоки для содержимого 
отдельных страниц. 
Дочерние шаблоны используют наследование: 
{% extends "base.html" %} 
Содержимое отдельных страниц размещается в блоке: 
{% block content %} 
{% endblock %} 
Заголовок страницы задаётся через блок: 
{% block title %} 
{% endblock %} 
### Включаемые шаблоны 
Повторяющиеся фрагменты вынесены в отдельные шаблоны. 
Для помещений используется: 
rooms/includes/room_card.html 
Для отображения состояния бронирования: 
bookings/includes/booking_status.html 
Подключение выполняется с помощью: 
{% include "rooms/includes/room_card.html" %} 
или: 
{% include "bookings/includes/booking_status.html" %} 
### Контекст 
Представления передают данные в шаблоны через словарь контекста. 
Например, для списка помещений: 
context = { 
    "rooms": rooms_list, 
} 
В шаблоне данные доступны по имени переменной: 
{% for room in rooms %} 
Для страницы отдельного помещения используется переменная: 
{{ room }} 
Аналогичный подход используется для бронирований. 
### Циклы и условия 
Для формирования списков используются циклы:

{% empty %}

2.6. Работа с базой данных из Python 
Создайте модуль подключения db/database.py и скрипт переноса данных 
db/import_json.py (подраздел 5.5). При работе с базой данных из Python: 
• подключайтесь к базе данных через sqlite3.connect(); 
• включайте проверку внешних ключей командой PRAGMA foreign_keys = ON; 
• выполняйте вставку нескольких записей методом executemany(); 
• передавайте значения в SQL-запросы через параметры ?; 
• сохраняйте изменения командой commit().

3. ТЕОРЕТИЧЕСКИЕ СВЕДЕНИЯ 
3.1. База данных и СУБД 
База данных – организованное хранилище данных, предназначенное для их со-
хранения, поиска и обработки. 
Система управления базами данных (СУБД) – программное средство, обеспечи-
вающее создание, хранение, изменение и получение данных из базы. 
В рамках практической работы используется СУБД SQLite.  SQLite хранит базу 
данных в одном файле. Для учебного индивидуального проекта это позволяет создать 
полноценную реляционную базу без установки и настройки отдельного сервера 
СУБД. 
3.2. Реляционная модель данных 
В реляционной базе данных информация представляется в виде таблиц.  Основ-
ные элементы таблицы: 
• таблица – набор данных об однотипных объектах; 
• строка (запись) – отдельный объект; 
• столбец (поле) – отдельное свойство объекта. 
Например, таблица rooms может хранить сведения о помещениях: 
id name capacity room_type 
1 Аудитория 101 30 учебная 
2 Конференц-зал 80 конференц-зал 
3 Переговорная 201 12 переговорная 
3.3. Типы данных в SQLite 
SQLite использует пять основных классов хранения: 
• INTEGER – целые числа; 
• REAL – вещественные числа; 
• TEXT – текстовые данные; 
• BLOB – двоичные данные; 
• NULL – отсутствие значения. 
При проектировании таблиц необходимо выбирать тип данных в соответствии с 
назначением поля. Например: 
CREATE TABLE rooms ( 
    id INTEGER,

    capacity INTEGER, 
    area REAL, 
    description TEXT 
); 
3.4. Первичный и внешний ключ 
Первичный ключ (PRIMARY KEY) однозначно идентифицирует запись таблицы. 
Например: 
CREATE TABLE rooms ( 
    id INTEGER PRIMARY KEY, 
    name TEXT, 
    capacity INTEGER 
); 
Поле id позволяет однозначно определить помещение.  Внешний ключ 
(FOREIGN KEY) используется для ссылки на запись другой таблицы. 
Например, бронирование связано с помещением и пользователем: поля 
bookings.room_id и bookings.user_id ссылаются на первичные ключи таб-

учитывают NULL при соответствующих вычислениях.

• PRIMARY KEY определяет уникальный идентификатор записи; 
• FOREIGN KEY определяет связь записи с другой таблицей; 
• NOT NULL запрещает сохранять в поле значение NULL; 
• DEFAULT задаёт значение, которое используется, если поле при вставке не указано. 
Для таблицы bookings внешние ключи обеспечивают связи:

COUNT(bookings.id) AS bookings_count 
FROM rooms 
JOIN bookings 
ON rooms.id = bookings.room_id 
WHERE bookings.is_cancelled = 0 
GROUP BY rooms.id, rooms.name 
HAVING COUNT(bookings.id) > 1 
ORDER BY bookings_count DESC; 
Различие между WHERE и HAVING принципиально: WHERE фильтрует отдельные 
записи до группировки, HAVING – группы после группировки. Порядок обработки 
частей запроса: 
FROM / JOIN 
↓ 
WHERE 
↓ 
GROUP BY 
↓ 
HAVING 
↓ 
ORDER BY 
Выполните запрос в SQLite CLI. Для текущего набора данных результат будет 
пустым: каждое помещение имеет не более одного активного бронирования. Пустой 
результат является корректным – условию HAVING не удовлетворяет ни одна группа. 
Примечание. Запрос демонстрирует работу HAVING на данных проекта. Его практический 
смысл проявится по мере накопления данных: добавьте в таблицу bookings несколько дополни-
тельных записей и проверьте, как изменится результат.

P25: Проект — «Система бронирования фотостудий». Создан Django-проект photostudio и приложения homepage, studios и bookings.
