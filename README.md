# Система бронирований фотостудий 

## Назначение проекта
Система бронирований фотостудий - приложение для поиска фотостудий и бронирования времени для фотосессий. 

## Целевая аудитория
- Профессиональные и начинающие фотографы.
- Частные клиенты, организующие фотосессии.
- Компании, проводящие рекламные и предметные съёмки.

## Описание предметной области 
Фотостудии предоставляют в аренду оборудованные залы для фото и видеосъёмок. Каждый зал имеет свои данные (информацию): площадь, интерьер, доступное оборудование и стоимость аренды за час.
Для организации съёмки клиент выбирает зал, дату, время начала и продолжительность аренды. Система проверяет доступность выбранного временного интервала и рассчитывает стоимость бронирования. Один зал не может быть забронирован несколькими клиентами на пересекающиеся временные интервалы.

## Практическая работа 3: объектная модель

Приложение остаётся консольным. Сценарии ПР2 сохранены: регистрация,
вход, каталог, поиск, информация о студии, выбор дня и почасового
интервала, расчёт стоимости, сохранение и просмотр собственных броней.
Добавлена отмена собственных бронирований без удаления истории.

### Классы, атрибуты и методы

| Класс | Атрибуты | Основные методы |
| --- | --- | --- |
| `Studio` | `id`, `name`, `area`, `price_per_hour` | `__init__`, `calculate_price`, `__str__` |
| `User` | `id`, `login`, `_password`, `is_active` | `__init__`, `check_password`, `to_data`, `__str__` |
| `Booking` | `id`, `studio`, `user`, `booking_date`, `start_hour`, `end_hour`, `total_price`, `is_cancelled` | `__init__`, `cancel`, `get_status`, `overlaps`, `__str__` |

Коллекции содержат экземпляры классов: `list[Studio]`, `list[User]`,
`list[Booking]`. Бронь связана с уже созданными объектами студии и клиента:
`booking.studio.name`, `booking.user.login`. Классы имеют конструкторы,
строковое представление, аннотации типов и документацию методов.

Инкапсуляция: проверка пароля выполняется через `check_password`, а
изменение статуса брони — через `cancel`. `_password` обозначает внутренний
атрибут по соглашению Python, а не технический запрет доступа.
Полиморфизм: `print()` одинаково вызывает `__str__` у разных классов.
Связь Booking с User и Studio выражена хранением ссылок на объекты.
Наследование не добавлено: бронь не является разновидностью пользователя
или студии. Декораторы для этой модели не потребовались.

### Что стало с функциями ПР2

- `add_studio`, регистрация и `create_booking` создают и возвращают объекты.
- Поиск, фильтрация, сортировка и проверка доступности остаются функциями
  обработки коллекций, но обращаются к атрибутам объектов.
- Расчёт цены перенесён в `Studio.calculate_price`, проверка пароля — в
  `User.check_password`, проверка пересечения — в `Booking.overlaps`.
- `show_studios` и `show_bookings` используют `__str__`.
- Ввод и файловые операции остаются обычными функциями.
- `cancel_booking` проверяет принадлежность брони и вызывает её `cancel`.

### Правила бронирования

Рабочие часы — с 9 до 18, интервалы состоят из целых часов в пределах дня.
Дата вводится как `2026.09.21`, хранится как `2026-09-21`.
Соседние интервалы разрешены; пересечения активных броней одной студии
запрещены. Отменённая бронь сохраняется в истории и не блокирует время.
Стоимость фиксируется при создании: изменение тарифа студии не изменяет
цену сохранённой брони. Проверяется существование даты, но прошедшие даты
пока не запрещены.

### Хранение и перенос данных

JSON остаётся форматом хранения. В файле брони записываются `studio_id`
и `user_id`; при загрузке они преобразуются в ссылки на объекты.
Несуществующая ссылка вызывает ошибку загрузки, а не создание неполной
брони. Сначала загружаются студии и пользователи, затем бронирования.

При переходе с ПР2 существующим пользователям добавлены идентификаторы.
Две старые записи без владельца сохранены за техническим пользователем
`archive_pr2` с `is_active: false`. Это не реальный клиент; вход для него
запрещён. Даты и часы старых записей сохранены. Новые брони принадлежат
вошедшему пользователю.

При записи сначала создаётся соседний временный JSON, затем заменяется
основной файл; временный файл удаляется после операции. При ошибке
сохранения меню не подтверждает успех и не меняет состояние в памяти.
Программа рассчитана на один запущенный экземпляр.
Пароли пока хранятся открыто в учебном JSON — для реального приложения
понадобится хранение хешей.

### Структура проекта

```text
main.py                    — меню и пользовательские сценарии
module/studios.py          — Studio и функции каталога
module/users.py            — User, регистрация и вход
module/bookings.py         — Booking, доступность, создание, отмена
module/storage.py          — загрузка/сохранение объектов через JSON
module/utils.py            — безопасный ввод
data/studios.json          — студии
data/users.json            — пользователи
data/date_of_booking.json  — бронирования
tests/test_*.py            — отдельный файл для каждого модуля
req.txt                    — инструменты проверки
```

Добавление студий и фильтрация по цене доступны через функции модуля.
Консольное меню предоставляет просмотр, поиск и сортировку по цене.

### Запуск и проверки

Требуется Python 3.9 или новее. Из корня проекта:

```powershell
python -m pip install -r req.txt
python main.py
python -m pytest -v
python -m flake8 --extend-exclude=.venv,venv,__pycache__,.pytest_cache,.mypy_cache
```

Тесты ПР2 адаптированы, а не удалены по назначению. Проверяются атрибуты,
методы, строковое представление, связи объектов, пересечения, отмена,
повторное бронирование, JSON, ошибочный ввод и сценарии меню. Файловые
проверки используют временный каталог pytest и не изменяют `data/`.
